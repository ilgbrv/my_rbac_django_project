# Система управления доступом на основе ролей (RBAC)

Backend-приложение  - система аутентификации и авторизации

## Архитектура базы данных

В проекте реализована структура таблиц без использования стандартных групп Django:
1. **CustomUser** — модель пользователя (авторизация по `email`, поддержка отчества, мягкое удаление через `is_active=False`).
2. **Role** — справочник ролей (Админ, Студент, Преподаватель). Связь с пользователями — Many-to-Many.
3. **Action** — справочник атомарных действий (`view`, `create`, `delete`).
4. **Resource** — справочник бизнес-объектов (`Homework`, `Projects`, `Tasks`).
5. **Permission** — таблица-мост, связывающая конкретное действие с конкретным ресурсом.

## Реализованный функционал

### Модуль 1: Аутентификация
* **Регистрация**: `POST /api/register/` (с валидацией совпадения паролей).
* **Логин**: `POST /api/login/` (выдача JWT-токенов `access` и `refresh` по email).
* **Мягкое удаление**: `DELETE /api/delete-account/` (перевод флага в `is_active=False` и автоматический Logout через Blacklist токенов).

### Модуль 2 и 3: Авторизация и Mock-данные
* Написан кастомный класс ограничений `CustomRBACPermission`, динамически проверяющий права пользователя в БД.
* Неавторизованные запросы возвращают ошибку `401 Unauthorized`.
* Пользователи без нужных прав получают ошибку `403 Forbidden`.
* Доступен тестовый эндпоинт проектов `GET /api/projects/`, защищенный кастомной системой прав.

## Быстрый старт для проверки

1. **Активация окружения**:
   ```bash
   .\venv\Scripts\Activate.ps1
   ```
2. **Запуск сервера**:
   ```bash
   python manage.py runserver
   ```
3. **Вход в панель администратора** для управления тестовыми данными: `http://localhost:8000/admin/`
