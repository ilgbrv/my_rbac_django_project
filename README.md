# Система Аутентификации и Авторизации (Кастомный RBAC)

Проект представляет собой кастомную систему управления доступом к ресурсам, реализованную на **Django REST Framework** и **SQLite** (поддерживает Postgres). Приложение написано без использования встроенных тяжелых библиотек аутентификации.

## 1. Аутентификация (Проверка подлинности)
* **Хеширование паролей**: В БД пароли хранятся в виде безопасных хешей. Использована библиотека `bcrypt`. Стандартный джанговский механизм `set_password` полностью переопределен в модели `CustomUser`.
* **Выпуск JWT-токенов**: При успешном логине (`/api/login/`) система вручную генерирует JWT-токен через чистую библиотеку `PyJWT`. В payload зашивается `user_id` и время жизни токена (2 часа).
* **Идентификация пользователя**: Написан кастомный `CustomJWTAuthenticationMiddleware`. На каждый запрос он перехватывает заголовок `Authorization: Bearer <token>`, декодирует его и связывает пользователя с объектом `request.user`. Если токен невалиден или отсутствует, пользователь помечается как `AnonymousUser`.
* **Мягкое удаление (Soft Delete)**: При удалении аккаунта у пользователя выставляется флаг `is_active=False`. Система разлогинивает пользователя, а Middleware и LoginView блокируют любые последующие попытки входа для этой учетной записи.

## 2. Авторизация и Схема контроля доступа (Матрица прав)
Для управления ограничениями доступа спроектирована и реализована гибкая плоская таблица-матрица `AccessRoleRule`. Доступ разграничивается на основе роли пользователя и конкретного бизнес-элемента (ресурса).

### Структура БД для авторизации:
1. **Таблица `Role`**: содержит список ролей в системе (`student`, `teacher`, `admin`).
2. **Таблица `AccessRoleRule`**: содержит правила доступа роли к определенному блоку приложения. Поля таблицы:
   * `role_id` — связь с ролью;
   * `element_name` — имя защищаемого ресурса (например, `projects`, `homework`);
   * **Права на свои объекты (Context-based)**: `read_permission`, `create_permission`, `update_permission`, `delete_permission`;
   * **Права на ВСЕ объекты в базе (Global)**: `read_all_permission`, `update_all_permission`, `delete_all_permission`.

### Пример работы матрицы прав (Бизнес-логика):
* **Студент** на ресурс `projects` имеет флаги: `read_permission=True` и `update_permission=True`. Это значит, что он может читать и редактировать **только те проекты, где он является автором (owner)**. Попытка изменить чужой проект вызовет ошибку `403 Forbidden`.
* **Преподаватель/Админ** имеет флаги: `read_all_permission=True` и `update_all_permission=True`. Это глобальный доступ, позволяющий просматривать и редактировать абсолютно любые объекты в базе данных, независимо от того, кто их создал.

## 3. Как запустить проект локально
1. Установите зависимости: `pip install -r requirements.txt`
2. Примените миграции: `python manage.py migrate`
3. Создайте суперпользователя (Администратора): `python manage.py createsuperuser`
4. Запустите сервер: `python manage.py runserver`
